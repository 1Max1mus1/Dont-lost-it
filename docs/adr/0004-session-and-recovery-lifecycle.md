# ADR 0004：当前守护、暂离与独立找回记录的生命周期

## 状态与证据

2026-10-28（Asia/Shanghai）整理。产品行为已在设计访谈中逐项确认；架构落地与设备能力尚未验证，保持 `draft`。

这是对 [ADR 0003](0003-privacy-by-default.md) 照片生命周期的补充，不改变默认删除完整原图和不记录路线的约束。

## 背景

当前任务必须指向一个明确场所，但用户可能已结束该地点核对，仍有物品需要之后寻找。若把寻找状态无限绑定为当前任务，就会阻止用户在新地点继续使用。与此同时，结束任务后保留整张原图与现有隐私约束冲突，暂离到期直接恢复报警也会把超时吃饭误判为遗漏。

## 决策

1. 同时最多一个当前守护任务。待找回记录独立保留，不阻止下一次守护。用户进入寻找中时仍可继续核对，也可明确结束本次核对并留下待找回记录。
2. 草稿不算当前守护，自动保留一份供继续或丢弃。确认开始前不得呈现后台保护已生效。
3. 当前清单可追加物品，沿用同一地点和手账卡。历史快照保护针对后续物品档案修改，不禁止当前任务中用户明确追加，也不禁止追加带日期的找回结果。
4. 手动守护不依赖有效定位或新图片。物品可以使用已有贴纸或手写名称标签；定位不可用时不虚构 Guard Point 或自动离场能力。
5. 暂离保留任务，只暂停离场提醒。选择的时长到期仍在远处时，仅发一次中性提示；未回应继续暂停。可靠返回观测或“我回来了”恢复提醒。暂离不表示物品受到防盗保护。
6. 待找回记录只在本机保留该物品及附近的局部照片，默认删除完整原图；无照片输入则无照片证据。找回后删除局部照片，除非用户主动保存。用户显式保存原图的既有例外仍成立。
7. 后续找回更新独立记录及历史卡的“已找回 / 实际找回日期”，不改写原始离场结果、不补盖“全员归队”。“找回啦”是不同的反馈事件。

## 模块影响

- Guard Session 管理当前任务、暂离与明确结束，不要求所有找回记录先解决才释放当前名额。
- Personal Inventory 允许物品暂时没有 Sticker Variant，界面使用名称标签。
- 原照片资源生命周期必须先保留需要的局部证据，再按默认规则删除完整原图；具体存储 schema 和事务机制在工程设计阶段选择。
- Journal 保留原始离场结果，追加后续找回日期与展示状态。
- Departure Detection 提供可验证的离场与返回观测；Reminder Policy 区分到期中性提示与离场报警。

## 后续验证

- 真机测定短距离过滤、返回判定与后台通知限制。
- 验证用户能区分草稿、手动守护、暂离暂停和待找回记录。
- 验证暂离长期无回应的误解风险，以及无定位情况下的手动恢复。
- 实现后验证完整原图删除、局部证据保留和找回后的清理，并确认历史离场结果没有被重写。
