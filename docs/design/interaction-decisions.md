# 低保真设计决策记录

整理日期：2026-10-28（Asia/Shanghai）。

证据来源：本项目聊天中的逐项设计访谈及用户明确答复。以下决策已由用户确认，但尚未经过原型测试、真实用户测试或真机验证，因此页面状态保留为 `draft`。本页记录决策及理由；正式产品要求同步见 [PRD](../PRD.md)，流程见 [用户流程](user-flows.md)。

## 首页、导航与草稿

| ID | 已确认决策 | 说明 |
|---|---|---|
| d-01 | 首次打开直接进入空白的今日手账 | 不设置独立引导页。用一句话说明用途，主按钮为“剪下今天带来的东西”；权限解释放在对应操作时。 |
| d-02 | 底部只有“手账 / 物品栏” | 历史手账通过日历查看，包包模板归入物品栏，设置在右上角。 |
| d-03 | 自动保留一份未完成草稿 | 首页提供“继续整理 / 丢弃”。草稿未确认开始前，不表示正在守护。 |

## 收集物品与开始守护

| ID | 已确认决策 | 说明 |
|---|---|---|
| d-04 | 重要程度在贴纸确认页设置 | 每件物品提供可选的“重要”开关，不增加必须逐件分类的独立流程。 |
| d-05 | 显式提醒补充未入镜物品 | 清单下方显示“还有没拍到的东西吗？”和“添加物品”，不增加必答弹窗。 |
| d-06 | 没拍到且没有已有贴纸的物品，用手写名称标签表示 | 不虚构实物图片；以后拍到实物时可再生成贴纸。已有物品可复用已有贴纸。 |
| d-07 | 识别或抠图失败仍可继续 | 同时提供“重试”和“手动添加物品并开始守护”。 |
| d-08 | 新物品名称集中确认 | AI 提供可编辑的建议名称，在同一确认页检查；已有身份不明确时再单独选择。 |
| d-09 | 保留“从已有物品开始” | 从物品栏或包包模板选择本次物品，沿用已有贴纸，不要求每次重新拍照。 |
| d-10 | 包包模板默认不勾选 | 用户选择今天实际携带的物品，也可使用“全选”；模板本身不证明本次携带。 |
| d-11 | 首次守护提供权限分流 | 清单确认后先说明，提供“开启自动提醒 / 先用手动核对”。选择自动提醒时再请求系统权限；拒绝后可手动守护。 |

## 当前守护与暂离

| ID | 已确认决策 | 说明 |
|---|---|---|
| d-12 | 同一时间只开启一个守护任务 | 到新地点想开始新任务时，先核对旧任务。独立的待找回记录不阻止开始新任务。 |
| d-13 | 守护中允许补充物品 | 支持拍照、物品栏和手写名称，沿用当前地点与手账卡，不重建任务。 |
| d-14 | 始终提供“准备离开，开始核对” | 开启了自动提醒，也可以主动开始核对，不必等待定位提醒。 |
| d-15 | 近距离活动由离场判定过滤 | 去洗手间、附近走动不应依靠用户点“暂离”来避免误报。结合距离、持续移动与定位精度判断；具体阈值待真机测试。 |
| d-16 | “只是暂离”面向较远距离的有意离开 | 例如物品留在图书馆，用户去吃饭或小卖部。保留任务和清单，只暂停离场提醒，回来后继续。不是物品安全或防盗承诺。 |
| d-17 | 返回后自动恢复，并提供手动恢复 | 定位可靠时回到守护点后自动恢复；页面保留“我回来了”。定位不可用时可手动恢复。 |
| d-18 | 暂离到期不自动变成遗失报警 | 沿用 10 / 30 / 60 分钟选择。到期仍在远处时只提示一次“还没回来？可延长暂离或开始核对”；用户未回应时仍暂停，直到返回或主动处理。 |

## 核对、遗失与找回

| ID | 已确认决策 | 说明 |
|---|---|---|
| d-19 | 普通物品支持逐件及批量确认 | 每件可选“已带走 / 还没找到”；普通物品有一键确认，重要物品仍须逐件确认。 |
| d-20 | 可以带着待找回记录结束本次核对 | “暂时找不到”后可结束当前核对，保留独立记录，不盖“全员归队”，也不阻止新守护任务。 |
| d-21 | 待找回只保留局部照片证据 | 在本机保留失物及周围一小块照片，按默认规则删除整张原图；找回后删除局部照片，除非用户主动保存。无照片的名称物品不生成虚假照片证据。 |
| d-22 | 后续找回不改写原来的离场结果 | 历史卡片由“待找回”改为“已找回”，标记实际找回日期；不补盖“全员归队”。 |
| d-23 | 找回提供专属情绪反馈 | 确认找回时，让贴纸回到手账并盖“找回啦”印章；只在确认时播放，回看保持静态，提供减少动态效果版本。用户明确提出应突出软件作用并给予情绪价值。具体时长、曲线和无照片标签的动效细节待设计。 |

## 尚未完成或未定的内容

- 已依据上述规则制作[低保真页面清单与可点击原型](low-fidelity-page-inventory.md)；Figma 高保真文件和新用户可用性测试尚未完成。
- 用户已选择[复古 Traveler's Notebook 手账拼贴方向](visual-direction.md)并制作三张视觉样页；最终品牌名称、字体、完整设计 tokens 和动效参数仍未定稿。
- 距离、持续移动和返回判定阈值，以及 iOS 后台能力，仍需要技术验证；短距离过滤是设计目标，不是已实现的可靠性承诺。
- 用户暂离到期后不回应可能长期暂停提醒，应在原型测试中检查用户是否理解当前状态。
- 用户丢弃草稿时的具体确认样式、草稿保存期限、守护中移除物品及已确认物品的修改规则，尚未逐项确认。
- 手动模式在无定位时的地点标签、授权不完整及后续补授权的详细流程待细化。
- 可点击原型中的开发者走查不代表用户已经理解这些规则，阶段 1 的可用性门槛仍未通过。
